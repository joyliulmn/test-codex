# V1.X 全A股数据层 V0.2 设计

## 目标

V0.1只解决两个问题：

1. 让V1.X拥有一个可持续更新的全A股OHLCV地基；
2. 先用客观事实做高召回粗筛，把“值得读的股票”从全市场捞出来。

它暂时不试图把L1/H1、主力意图或全部V1.X经验硬编码成一个万能公式。

## 数据源

第一版零密钥使用AKShare封装的东方财富公开行情：

- `stock_zh_a_spot_em()`：全沪深京A股当日快照；
- `stock_zh_a_hist()`：单股历史日线，不复权。

后续可以加入Tushare作为第二数据源用于校验与补洞，但V0.1不要求用户先申请Token。

## 数据库

SQLite先满足本地单机需要。主表 `daily_bar` 以 `(trade_date, code)` 唯一，避免重复更新。

关键字段：OHLC、昨收、涨跌幅、成交量、成交额、振幅、换手率。

第一次历史回填从2020年起；之后每日只追加当天快照。

交易日不再从`daily_bar`中“碰巧出现过的日期”推断。`trade_calendar`保存交易所
会话日历，扫描SQL在完整日历上生成`market_session_number`；即使某只股票停牌、
数据库缺一日，连板也会被正确断开。每日更新还必须用上证指数当日已完成日线
二次确认会话，休市日或接口尚未形成收盘日线时直接失败，绝不把旧快照贴成今天。

写入前执行全市场完整性闸门：至少3000个有效代码，沪深京三地分别至少
800/800/30个代码，至少85%具有正收盘价；若库中已有前一交易日，还要求总数
不少于前日95%，前一会话已记账代码必须100%延续，每个交易所不少于前日90%；
若权威上一会话存在但整日行情缺失也会失败。失败会
写入`daily_update_audit`但不会写入当日日线。扫描前会再次从数据库重算同一闸门，
并要求最新日线等于日历最新已确认会话，避免部分数据对自身候选集合做出
“覆盖PASS”或继续扫描旧日期。

数量阈值只是异常检测，不能单独生成`PASS`。独立代码表中的每个代码必须由可用行情
或东方财富当日全时段停牌台账逐码覆盖，沪深京各自至少85%的行情代码具有完整OHLCV，
并与至少两个带日期的个股收盘锚一致；
有前一会话时，至少95%的可比代码必须具有有效参考价证据（优先`pre_close`，缺失时
才允许由涨跌额或涨跌幅反推），其中至少95%的普通参考价还必须与库内前收一致；
经涨跌额/涨跌幅交叉印证的除权参考差异单列审计，不混入普通匹配率；允许单只例外，
但系统性差异超过参考样本5%即失败，防止同源字段自洽却整体错误。扫描器要求目标会话
存在上述更新流程写出的`PASS`审计，并复算代码集合哈希与完整快照内容哈希；孤立于
交易日历的任何日线日期、修改后的代码集合、PASS后被改写的行情/限价元数据或缺少
审计回执都会中止发布。历史回填也不得覆盖已经验真的`SPOT_SAME_DAY`行情字段。

停牌例外不是汇总比例豁免。生产`update`只接受目标当日、覆盖完整交易时段且分页/行数/
字段均可验证的停牌记录；其逐码证据写入`daily_suspension`，并把
`suspension_rows`、`suspension_source`、`suspension_hash`、官方全集内停牌比例和
官方/前日代码全集指纹写入`daily_update_audit`。停牌比例超过5%时失败并要求人工复核。
扫描前从库内重算这些证据；台账被删除或改写、停牌接口失败，
以及既无可用行情又无全日停牌证明的官方代码，都会失败关闭。停牌台账仅保留与
同日官方A股全集相交的代码；其余官方代码必须同时具有完整OHLCV与非空点时名称，且
官方名称与行情名称的ST状态必须一致，避免主板ST错误回退到10%涨停规则。非空但无法
解析的停牌起止时间不能被当作无限期停牌。

当日市场快照通过完整性检查后，`update`还请求东方财富当日涨停股池。程序直接
使用封板行的`最新价`作为精确涨停价，并保存接口的`连板数`及
`EASTMONEY_LIMIT_UP_POOL`来源；写库前逐代码核对其属于完整快照且收盘价一致。
审计保存池行数、来源与内容哈希，扫描前从库内重算，防止元数据在PASS后被删除或
改写。AKShare对该上游只声明可查“近期”而没有精确天数，且空结果无法区分合法
零涨停与`data=null`，所以生产只查已确认的中国市场当日，并把空池、错日、结构
漂移和任何对账差异都视为失败；不以该接口做任意历史回填。

东方财富主涨停池不包含ST。全市场当日快照中的点时证券名称会把主板ST的5%状态
落为`SPOT_SAME_DAY_STATUS`，从启用后的下一交易日起可据前日状态自然计算连板。
若当前ST涨停而相邻前日只有`CURRENT_UNIVERSE_BACKFILL`名称或缺少点时涨跌停
元数据，序列标记为`UNKNOWN_PREVIOUS_LIMIT_STATE`：`is_first_limit_up`不置真、
`limit_up_streak`不伪造为1，但该股票仍以`LIMIT_UP_SEQUENCE_UNVERIFIED`进入
强制实名台账。
同日重跑的坏行情既不能通过完整性闸门，也不能覆盖库内已有好行情。完整日历刷新
会撤销权威区间内已被纠正的伪会话；对应V0.1遗留日线不会直接销毁，而是连同原始字段、
原因、来源和隔离时间移入`daily_bar_quarantine`，`doctor`汇总隔离行数与日期数。

## 历史盲测原则

主库保留不复权数据。原因：前复权会随着未来除权除息重新改写历史价格，不利于严格还原当时看到的盘面。

## V1.X特征层 V0.1

第一版只计算可观察事实：

- 1日价格位移；
- 日内振幅；
- 5/20日均量与振幅；
- 相对成交量；
- 攻击K候选；
- 最近攻击距离；
- 攻击收盘价是否被保留；
- 5日重心是否下移；
- 5日量能是否较20日收缩；
- 5日波动是否较20日收缩；
- 第二次点火前置窗口。

其中“第二次点火前置窗口”只是候选发现条件，不等于自动买入。

## V0.2已落地：首板防漏与报告审计

V0.2不把“给首板加分”当作修复。最高分股票仍可能在短Top-N中被静默截断，
因此把发现、比较和买入权限拆开：

1. `price_attack_k`登记所有涨幅达到5%的收盘正向位移；旧字段
   `attack_k == fire_k`保持不变，避免破坏既有CSV消费者；
2. `attack_registry`登记所有`price_attack_k`及实际涨停；
3. `mandatory_accounting`登记所有首板与连板，保证实名台账可核对；
4. `mandatory_compare_seed`标记高质量首板、连板和点火前置窗口；
5. 报告集合固定为“首板/连板实名台账 ∪ 强制比较全集 ∪ 常规Top-N”，
   不能先`head(N)`再找板块；
6. 强制比较只要求必须解释，0U/1U仍由板块、周线、风险锚和成交性决定。

历史接口缺失`pre_close`时，参考价依次使用精确涨跌额反推值、与四舍五入涨幅
相容的数据库前收、涨幅反推值，并输出`pre_close_source`；精确涨跌额一旦显示
除权参考价与未复权前收不同（哪怕高价股只差一分钱），即采用反推参考价。
`pre_close<=0`和非有限值均视为缺失，不参与位移或攻击判断。若输入带有有效的
`daily_limit_pct`或`limit_up_price`及来源，交易所时点元数据优先，
`RULE_FALLBACK`只在对应元数据缺失时启用。生产SQL同时在全历史上计算`listing_trade_number`
和权威交易日历序号，避免把短加载窗口误当成IPO窗口，也避免停牌跨日被误算连板。

历史回填使用当前证券名称时写入`name_source=CURRENT_UNIVERSE_BACKFILL`，不会再
用该名称倒推历史ST状态。输出同时携带`point_in_time_state_unknown`和
`future_data_status`；未知状态写为未知，不能伪装成`future_data_used=False`。

`validate_candidate_coverage()`从当日完整横截面独立重建攻击、首板、连板和机器
强制比较集合，再与候选集合逐代码核对。`first_seen_date/first_planned_date`只沿用
最近一期扫描中仍连续存在的代码，避免跨候选断档继承旧 episode；历史回放不读取
晚于`as_of_date`的文件。`report_included`只表示机器计划纳入，绝不自动写入
`first_reported_date`。后者只有在发布器调用`v1xdata receipt`写入带 ID 和时间戳的
显式 delivery receipt 后才成立；旧 CSV 中没有回执凭证的同名字段不再被信任。

当前仓库尚无带时间快照的行业/概念成员映射。因此
`mandatory_compare_seed`只是机器防漏种子，不冒充已完成语义板块门控；日报仍需完成
板块映射和同板块横向比较，并为0U给出明确原因码。

## 重要工程原则

- 数据层和解释层分离；
- 不把“主力目的”作为数据库字段；
- 每个新规则必须能回到原始价格/成交事实；
- 扫描器重在全市场发现，最终交易仍由V1.X证据链确认；
- 原始大数据不提交GitHub，GitHub只保存代码、测试和规则版本。
